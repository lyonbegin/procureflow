## 소스 접근에 대한 검증된 구별

- `data.go.kr`의 **목록 페이지가 열리는 것은 실제 CSV/XLSX 수집 성공이 아님**. 카탈로그와 보고서 본문을 별도로 검증한다.
- `https://data.g2b.go.kr/`는 2026-11-16 확인 시 `sso.g2b.go.kr` OIDC 로그인으로 리디렉션되었으므로, 공식 로그인이나 공개 직접 다운로드 경로가 확보되지 않으면 자동 수집 완료로 표시하지 않는다.
- OpenAPI는 공개 무료라도 **승인된 공공데이터포털 ServiceKey 필요**. 키를 추측하거나 저장소 코드/로그에 넣지 않으며, 별도 GitHub Actions Secret을 이용하는 방식만 허용. 아직 Secret 설정/실제 호출 확인 없음.
- 기존 2년 Stage 2: 저장 대상 187개 ZIP/상태 187개는 Release에 등록된 상태지만 원본 바이트 재해시·페이지/행 검증은 별도 작업이며, 신규 소스 확보를 이유로 원본 큐를 재수집하지 않는다.
- 모든 원본 기록에는 출처 URL, 가져온 시각, 원본 게시/수정일, SHA-256, HTTP 상태, 수집기 버전, 페이지 커서, 레코드 수, 고유키, 중복/누락 및 검증 결과를 함께 남긴다.
- 낙찰자선정여부=Y는 최종 계약 확정을 의미하지 않는다. 낙찰·계약·수의·납품요구는 서로 다른 레코드 유형으로 연결한다.
- 기간별 12년 데이터는 2014-11~2026-11을 초기 목표로 하되, 원본 서비스별 실제 제공기간·조회조건 및 누락을 기록한다.

## 단계별 실행 게이트

1. 각 데이터 원본의 **실제 응답과 다운로드 URL 검증**(접속 가능/인증 필요/일시 중단/자료 없음 구분). 인증이 필요한 데이터는 무리한 우회 금지.
2. 소스별 독립 GitHub-hosted `ubuntu-latest` 수집기와 체크포인트/영구 보존 Release 설계. 기존 10-worker Stage2 워크플로 및 두 기존 Release는 수정하지 않음.
3. 작은 기간/샘플 원본을 확보해 스키마와 원본 URL·SHA256 검사 후, 7일 또는 서비스별 허용 기간에 맞춰 백필/일별 신규 갱신.
4. 공고/차수/집행/업체/계약/공동수급/MAS 납품요구 간 정확한 키와 원본 증빙만 결합. 신규/기존 업체 이력 및 유찰 후 수의 전환도 명시적 관계만 인정.
5. 장기 시장발견 D01~D08, X01~X14, Y1~Y5, M1~M4는 실제 12년 원본 확보·검증 범위 내에서만 산출.
