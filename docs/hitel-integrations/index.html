HITEL · Integration API · v1

외부 프로그램용 ChatGPT 연동 API

앱·서버·자동화 프로그램에서 JSON 요청으로 대화방을 생성하고, 질문 작업을 접수하고, 결과를 조회하는 API입니다.

기본 호출 방식: HTTPS · JSON · Bearer 인증 · 비동기 작업 조회

운영 상태 안내 — 소스 및 격리된 자동시험에서 API 계약을 구현·검증했습니다. 외부 HTTPS 서버에 실제 배포되었는지, 등록하신 1번 ChatGPT 계정과 운영 환경이 연결되었는지는 별도 검증이 필요합니다. 아래 주소의 BASE_URL은 실제 배포·확인한 서버 주소로 교체해야 합니다. 등록 계정과 GitHub Actions의 Chrome은 동일한 사용자를 검증해야 하며, 작업 접수(202)는 실제 ChatGPT 답변 완료가 아닙니다.

인증키 발급 및 관리

최초 1회는 기존 HITEL 브라우저에서 소유권이 검증된 ChatGPT 계정을 선택해야 합니다. 그다음 발급받은 htli_... 형태의 API 키를 외부 프로그램의 비밀 설정값으로 보관하십시오. ChatGPT 로그인 쿠키·Google 비밀번호·GitHub 토큰을 외부 프로그램에 넘기지 않습니다.

발급 절차: 기존 HITEL 브라우저의 GET /web/api/bootstrap에서 세션과 CSRF값을 받은 다음, 동일 브라우저 쿠키와 X-Web-Csrf 헤더로 POST /web/api/integrations/keys에 {"name":"My application"}을 전송합니다. 계정이 검증·선택된 경우 키가 단 한 번 반환됩니다.

조회: GET /web/api/integrations/keys는 이름·ID·폐기 상태만 제공합니다. 비밀키 원문은 반환하지 않습니다.

폐기: 동일 브라우저 인증과 CSRF로 DELETE /web/api/integrations/keys/{key_id}를 요청합니다.

외부 프로그램은 브라우저 쿠키를 사용하지 않으며, 매 요청에 Authorization: Bearer $HITEL_API_KEY를 포함합니다. 선택한 계정이 해제되거나 다른 계정으로 변경되면 기존 키의 실행 권한이 자동으로 거부됩니다.

프로그램 연동 순서

  1. 계정 검증 후 통합 API 키를 발급받습니다.
  2. GET /integrations/v1/capabilities로 서버 지원 기능을 확인합니다.
  3. POST /integrations/v1/rooms로 해당 계정 전용 대화방을 생성합니다.
  4. POST /integrations/v1/chat로 질문을 접수합니다. 이때 요청에 선택된 account_id를 따로 넣고, Idempotency-Key를 지정합니다.
  5. 응답의 job_id로 GET /integrations/v1/jobs/{job_id}를 조회합니다. completed가 되어야 최종 답변입니다.

같은 방에서 후속 질문을 보내려면 직전 작업이 completed 상태이며 기존 ChatGPT 대화방 URL이 정상 연결되어 있어야 합니다. 상태가 불확실하면 중복 전송하지 않고 오류를 확인해야 합니다.

cURL 예제

서버 주소와 개인 API 키는 각 프로그램의 환경변수로 관리하시고, 소스나 GitHub Actions 로그에 직접 기록하지 마십시오.

1. 연결 정보

export BASE_URL="https://<배포-확인된-서버-도메인>"
export HITEL_API_KEY="htli_발급받은_비밀키"

curl -fsS "$BASE_URL/integrations/v1/capabilities"

2. 대화방 생성

curl -sS -X POST "$BASE_URL/integrations/v1/rooms" \
  -H "Authorization: Bearer $HITEL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"title":"외부 프로그램 시험방"}'

# 응답 예: {"room_id":"room_...","account_id":"oai_...","status":"active"}

3. 질문 접수 (HTTP 202)

curl -sS -X POST "$BASE_URL/integrations/v1/chat" \
  -H "Authorization: Bearer $HITEL_API_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: client-20261118-request-0001" \
  -d '{
    "room_id":"room_발급받은_대화방_ID",
    "account_id":"oai_선택한_계정_ID",
    "text":"안녕하세요. 한 문장으로 답변해 주십시오.",
    "attachment_ids":[]
  }'

# 응답 예: {"job_id":"job_...","status":"queued",
#            "accepted":true,"sent_to_chatgpt":false,"poll":"..."}

4. 결과 조회

curl -sS "$BASE_URL/integrations/v1/jobs/job_발급받은_작업_ID" \
  -H "Authorization: Bearer $HITEL_API_KEY"

# queued / running: 아직 답변 아님
# completed: result_text가 최종 답변
# failed: error가 오류 분류

오류와 안전 규칙

HTTP상황해결
400Idempotency-Key 누락 또는 형식 오류요청마다 고유한 16~128자 키 지정
401/403Bearer 인증 누락·폐기·잘못된 키실제 발급된 키인지 확인
409요청 계정 불일치·다른 계정 전환·작업 진행 중·중복키 충돌해당 키의 계정과 방을 확인, 진행 중이면 작업 조회
429요청 횟수·인증키 개수 제한불필요한 반복 전송 중단
501원본 파일 첨부·다운로드 미지원지원 구현 및 실측 전까지 파일 전송 중단

질문은 최대 2,000자이고, 기본 테스트 제한은 계정 프로필당 시간당 5회·브라우저 시험 대상 전체 하루 30회입니다. 작업이 실제 ChatGPT에 전달된 뒤 네트워크가 끊길 수 있으므로, 임의로 다른 Idempotency-Key를 발급하여 같은 질문을 재전송하지 마십시오.

보안: 한 API 키는 하나의 사용자 프로필과 하나의 검증된 ChatGPT 계정에 묶이며, 다른 계정이나 대화방의 메시지를 열람할 수 없습니다. 시스템이 계정 일치를 확인할 수 없으면 전송을 거부합니다.
