HITEL ChatGPT API — 링크 중심 간편 사용법

다른 프로그램에 아래 서버 주소를 전달하십시오. GitHub Actions 실행, GitHub App 생성, Railway 설정, 계정 재로그인은 필요하지 않습니다. 서버가 필요할 때 기존 워커를 자동 실행합니다.

1. 서버 접속 링크

https://hitel-integration-api-production.up.railway.app/integrations/v1/capabilities

이 URL은 누구나 바로 열어 연결 상태를 확인할 수 있습니다.

2. 실제 ChatGPT 텍스트 API

기본 주소: https://hitel-integration-api-production.up.railway.app

이미 발급된 HITEL 전용 연결키와 계정 식별자를 사용하는 프로그램만 실제 계정으로 질문을 보낼 수 있습니다. 이 값은 기존 사용자 계정을 임의로 공개하지 않기 위한 서버 내부 접근 통제이며 GitHub나 Railway에 다시 로그인하는 과정이 아닙니다.

POST /integrations/v1/rooms
Authorization: Bearer <기존 HITEL 연결키>
Content-Type: application/json

{"title":"새 대화"}

반환된 room_id와 account_id로 아래 요청을 보냅니다.

POST /integrations/v1/chat
Authorization: Bearer <기존 HITEL 연결키>
Content-Type: application/json
Idempotency-Key: user-request-20261119-00001

{"room_id":"<room_...>","account_id":"<oai_...>",
 "text":"질문 내용","attachment_ids":[]}

HTTP 202 응답의 job_id를 보관한 다음 해당 결과를 조회합니다.

GET /integrations/v1/jobs/<job_id>
Authorization: Bearer <기존 HITEL 연결키>

status=completed와 result_text가 있으면 답변이 완료된 것입니다. HTTP 202는 질문 접수만 의미합니다.

3. 자동 연결 및 장애 복구

워커가 꺼져 있으면 질문을 받았을 때 서버가 GitHub 작업자를 자동 실행합니다. 처리할 작업이 없다면 워커는 꺼져 있어도 됩니다. 기존 계정을 다시 등록할 필요는 없습니다.

4. 테스트 전 확인 사항

텍스트 질문은 실증 시험에 통과했지만 현재 등록된 외부 프로그램 키로 무인 자동 기동부터 답변까지 완주하는 실서버 시험은 아직 별도로 확인해야 합니다. TXT·CSV·PDF 등 외부 파일 첨부 및 파일 다운로드 API는 아직 지원하지 않습니다.

시간당 5건 및 하루 30건의 HITEL 자체 메시지 수 제한은 없습니다. 같은 대화방에서 미완료 질문을 동시에 두 번 보내거나, 동일 요청을 다른 Idempotency-Key로 반복 제출하지 마십시오.
